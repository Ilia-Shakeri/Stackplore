# Stackplore

**تمام سرویس‌های پشتهٔ خود را کاوش کنید.**

[English](README.md)

Stackplore یک فضای خودمیزبان برای مشاهدهٔ زیرساخت است. موجودی منابع، سلامت، توپولوژی، گزارش‌ها، سنجه‌های کنونی و رویدادهای هر منبع را در یک API نسخه‌دار و رابط واکنش‌گرای فارسی و انگلیسی یکدست می‌کند.

> **وضعیت:** نامزد اصلاحی `1.0.1`؛ پذیرش نهایی باز است. هر نه مرحله از نظر کارکرد پیاده‌سازی شده‌اند. نقطهٔ تغییرناپذیر `v1.0.0` آزمون‌های ثبت‌شده را گذراند، ولی پس از کشف پیش‌فرض آسیب‌پذیر PostgreSQL 17.6 و نبود اسکن تصویر پایگاه داده، انتشار آن لغو شد. هیچ GitHub release برای `v1.0.0` منتشر نشد. پیش‌انتشار `v0.9.0` نیز همان پیش‌فرض ناامن را دارد و کنار گذاشته شده است. [گیت‌های کنونی](docs/evidence/1.0.1/README.md) و [تاریخچهٔ نقطهٔ منتشرنشده](docs/evidence/1.0.0/README.md) مرجع وضعیت هستند.

نامزد پوش‌شدهٔ ۱٫۰٫۱ که فقط تصویر بالادستی را به کار برد، رد شد: گیت محلی و هر
۱۴ آزمون مرورگر گذشت، ولی [آزمون بستهٔ 39119787671](https://github.com/Ilia-Shakeri/Stackplore/actions/runs/39119787671)
در اسکن تصویر پایگاه شکست خورد. بررسی تازه، یک ایراد CRITICAL و ۲۴ ایراد HIGH
در کتابخانهٔ Go همراه `gosu` یافت؛ همه مانع انتشارند. تصویر مشتق PostgreSQL با
`gosu` بازساخته در کار است؛ ساخت، اجرا و اسکن آن هنوز باز است. ۱٫۰٫۱ تگ نشده و
پذیرفته نیست؛ [رسید شکست](docs/evidence/1.0.1/failed-database-image.json).

## پیاده‌سازی‌شده

- راه‌اندازی سرور فقط با PostgreSQL، استخر محدود، مهاجرت‌های پیش‌روندهٔ تعبیه‌شده، قفل مهاجرت و مالکیت، آمادگی سرویس و عملیات بومی `pg_dump` و `pg_restore`
- حساب مدیر و مشاهده‌گر، گذرواژهٔ Argon2id، نشست مبهم، حفاظت CSRF، اثبات احراز دوباره، راه‌اندازی نخستین، مدیریت کاربر و بازیابی توسط اپراتور
- درگاه‌های دامنهٔ مستقل از ارائه‌دهنده و منبع نمایشی قطعی با هویت پایدار، موجودی صفحه‌بندی‌شده، سلامت، توپولوژی، گزارش، سنجه و تاریخچهٔ رویداد
- کلاینت رسمی Docker و Kubernetes پشت مبدل محدود: مشاهدهٔ Docker از پراکسی محدود mTLS، خواندن Kubernetes در namespaceهای مشخص با پوشش مستقل موجودی، جزئیات نوع‌دار امن، بررسی UID گزارش Pod و سنجش عمر نمونهٔ سنجه. محدودیت و رسید محیط موقت در [Docker](docs/docker-provider.fa.md) و [Kubernetes](docs/kubernetes-provider.fa.md) ثبت است.
- دموی نسخه‌دار با نه منبع در دو محیط، زمان ثابت، مهمان ایزوله بدون حساب و نشست، منع نوشتن در سرور و ارسال بیرونی خاموش. شروع دوبارهٔ Demo عادی تأیید هشدار همان نسخه را حفظ می‌کند؛ استقرار ایزوله دادهٔ مشتق را بازنشانی و سابقهٔ محافظت‌شده را نگه می‌دارد؛ [راهنمای دمو](docs/demo.fa.md).
- ارجاع امن و ماندگار منبع و مشاهده‌های عادی‌شده؛ موجودی، سلامت، توپولوژی، سنجه و رویداد از PostgreSQL خوانده می‌شوند و گزارش خواندن زندهٔ محدود می‌ماند. جمع‌آوری سقف هم‌زمانی، لغو و فاصلهٔ افزایشی تلاش دوباره دارد؛ نگهداری محدود با سهم جدا، ممیزی محافظت‌شده را پاک نمی‌کند. [مشاهده‌ها و تنظیم منبع](docs/observations.fa.md) جزئیات را می‌گوید.
- قرارداد OpenAPI نسخه‌دار، نوع‌های تولیدشدهٔ مرورگر، بررسی سخت‌گیرانهٔ پاسخ، خطاهای امن، سقف درخواست، محدودیت نرخ، اعتماد پراکسی، زنده‌بودن، آمادگی و سنجه‌های محافظت‌شدهٔ فرایند
- نمای کلی، منابع، جزئیات، توپولوژی، گزارش، رویداد و هشدار صفحه‌بندی‌شده با فیلتر نشانی، وضعیت ناقص صادق، جایگزین قابل استفاده با صفحه‌کلید و پشتیبانی از فارسی راست‌به‌چپ و انگلیسی؛ [راهنمای بررسی مشاهده‌ها](docs/exploration.fa.md).
- روشن/خاموش‌کردن منبع توسط مدیر با هدف و نسخهٔ دقیق، مرور اثر، تأیید منقضی‌شونده و یک‌بارمصرف، احراز دوبارهٔ مخصوص همان کار و ممیزی اتمی؛ نمایه و اعتبارنامه را اپراتور تأمین می‌کند
- شواهد پوشش‌داده‌شده برای هر هشت شرط هشدار، مدیریت قانون توسط مدیر، چرخهٔ نمایشی ماندگار، بازپخش تغییر هشدار و اعلان پیونددار. مسیرهای وب‌هوک و ماتریکس اختیاری، وضعیت بدون راز، آزمون دارای احراز دوبارهٔ یک‌بارمصرف، محتوای ثابت، اجاره و ممیزی پایان دارند؛ [معنا و محدودیت](docs/alerts-notifications.fa.md) مرجع جزئیات است.
- یک تصویر Go بدون کاربر ریشه برای UI و API، Compose محلی ماندگار و نمودار خوشه با PostgreSQL خارجی. CI ساخت تصویر، نصب تازه و restart در Compose و نصب واقعی نمودار با TLS را می‌سنجد.
- پوستهٔ آفلاین عمومی و به‌روزرسانی با پذیرش کاربر، دانلود جریانی محدود گزارش پاک‌شده، فیلتر نشانی رویداد، تاریخچهٔ سلامت، روند سنجه و تازه‌سازی محدود موجودی و توپولوژی. نمایهٔ Kubernetes فایل توکن یا گواهی نصب‌شدهٔ اپراتور را می‌پذیرد؛ [راهنمای کاوش](docs/exploration.fa.md) و [نمایه‌ها](docs/kubernetes-provider.fa.md).

## کارهای لازم برای پذیرش ۱٫۰٫۱

- دروازهٔ کامل محلی، مرورگر، PostgreSQL 17.11، ارائه‌دهنده و استقرار میزبانی‌شده روی کد اصلاحی دقیق، همراه پشتیبان‌گیری بومی و بازیابی در مقصد خالی
- اثبات نسخه و digest موتور و ابزار تصویر مشتق پایگاه و افت دسترسی، اسکن کامل تصویر و SPDX هم‌بسته، به‌علاوهٔ اسکن بستهٔ بومی، برنامه، وابستگی و تاریخچه و بررسی مستقل بسته‌های امضاشده
- تگ دقیق `v1.0.1`، انتشار امضاشده و پذیرش بستهٔ عمومی؛ شمار مورد انتظار ۳۹ فایل، ۳۰ ورودی checksum،‏ همهٔ ۳۱ موضوع provenance و هفت گواهی SBOM بستهٔ بومی/برنامه/پایگاه است و هنوز تأیید نشده است

نمرهٔ بازبینی کنونی **۸ از ۱۰** است تا گیت‌های اجرای واقعی، استقرار و اسکن
نسخهٔ اصلاحی بگذرند. آزمون‌های موفق پیشین، شاهد تاریخی می‌مانند و پذیرش نسخهٔ
اصلاحی را ثابت نمی‌کنند.

استقرار تولید مشتری، تصمیم اپراتور همان محیط است. اعتبارنامه، دسترسی منبع،
دسترسی گیرنده، مقصد پشتیبان و ظرفیت باید طبق راهنما در همان محیط بررسی شوند.
شاهد محیط موقت، گواه سلامت استقرار تولید مشتری نیست.

## توسعه

از Node.js نسخهٔ `24.18.0`،‏ pnpm نسخهٔ `11.17.0` و Go نسخهٔ `1.26.9` استفاده کنید:

```sh
node scripts/bootstrap.mjs
corepack pnpm run check:contracts
corepack pnpm run verify
corepack pnpm run dev
```

وب توسعه روی `http://127.0.0.1:5173` و API روی `http://127.0.0.1:8080` اجرا می‌شود. آزمون یکپارچهٔ PostgreSQL فقط با پایگاه دادهٔ آزمایشی معرفی‌شده در `STACKPLORE_TEST_POSTGRES_URL` اجرا می‌شود.

راه‌انداز توسعه فایل `.env` ریشه را می‌خواند؛ اجرای مستقیم Go فقط محیط فرایند
را می‌خواند. برای توسعه از `.env.example` استفاده کنید. فایل `.env` مخصوص Compose
نام‌های فقط‌استقرار دارد که بارگذار سخت‌گیرانهٔ Go رد می‌کند؛ آن را بدون تغییر
برای توسعه به کار نبرید. [پیکربندی](docs/configuration.md) مرجع جزئیات است.

## استقرار

درخت اصلاحی، `stackplore-postgres:1.0.1` را از پایهٔ PostgreSQL 17.11 با digest
ثابت در [`deploy/postgres-image.json`](deploy/postgres-image.json) تعریف می‌کند.
کد دست‌نخوردهٔ `gosu` 1.19 با Go 1.26.9 بازساخته می‌شود؛ موتور و entrypoint
بالادستی می‌مانند. Compose و CI باید تصویر اصلاحیِ متعلق به محیط آزمون را
بسازند؛ آرشیو Docker-save و SBOM امضاشدهٔ آن هم در انتشار می‌آید. رسید ساخت،
اجرای واقعی و اسکن تصویر مشتق هنوز باز است. Helm همچنان PostgreSQL خارجیِ
متعلق به اپراتور را به کار می‌برد. پیش‌فرض کنارگذاشته‌شدهٔ پایگاه در 0.9.0 را
به کار نبرید. نصب موجود، پیش از تغییر تصویر پایگاه به
[روند بررسی‌شدهٔ ارتقای وصله](docs/operations/upgrade-rollback.fa.md)، پشتیبان
معتبر و زمان نگهداری اپراتور نیاز دارد.

برای Compose محلی، `deploy/compose.env.example` را به `.env` کپی کنید، جای‌نگهدارها را عوض کنید و سپس اجرا کنید:

برای پایگاه دادهٔ خالی، پیش از اجرا اثبات و انقضای کوتاه‌عمر راه‌اندازی را طبق
[راه‌اندازی نخستین](docs/operations/account-recovery.md) در محیط پوستهٔ اپراتور
بسازید. Compose این دو را عبور می‌دهد؛ آن‌ها را در `.env` ذخیره نکنید. نخستین
مدیر را در `/setup` بسازید، سپس مقدارها را حذف و فقط API را دوباره ایجاد کنید.
[مراحل کامل نصب](docs/operations/deployment.md) مرجع اجرای دقیق هستند.

```sh
docker compose up --build -d
```

حجم‌های نام‌دار دادهٔ PostgreSQL و کلید زمان اجرا را نگه می‌دارند. فرمان `docker compose down` آن‌ها را حفظ می‌کند. نمودار خوشه به Secret موجود با نشانی PostgreSQL خارجی و `sslmode=verify-full` نیاز دارد. [استقرار](docs/operations/deployment.md) و [پشتیبان‌گیری و بازیابی](docs/operations/backup-restore.md) را ببینید.

## امنیت

دسترسی ارائه‌دهنده حساس است. اطلاعات ورود را در سرور نگه دارید، دسترسی فقط‌خواندنی بدهید و گذرواژه، توکن، کلید خصوصی، محتوای kubeconfig، دادهٔ نشست، نشانی خصوصی یا گزارش پاک‌نشده را در مسئله‌ها و درخواست‌های تغییر قرار ندهید. روش گزارش خصوصی در [SECURITY.md](SECURITY.md) آمده است.
