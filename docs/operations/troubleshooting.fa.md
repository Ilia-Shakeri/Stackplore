# عیب‌یابی

اول کد ثابت خطا و تفاوت `/healthz` با `/readyz` را ببین. health فقط پاسخ‌گویی
فرایند است؛ readiness پایگاه، ledger و مالکیت runtime را هم می‌سنجد. از دسترس
یک provider، readiness کل را الزاماً خراب نمی‌کند. environment، راز، log خام یا
URL اعلان را برای پشتیبانی نفرست.

| نشانه | بررسی | گام امن |
| --- | --- | --- |
| برنامه پیش از listen می‌ایستد | کد خطای ثابت و نام تنظیمات | نام و قالب را با [مرجع پیکربندی](../configuration.fa.md) بسنج؛ مقدار را چاپ نکن. |
| API نصب تازه زود می‌میرد | پایگاه خالی، bind، جفت proof و expiry | proof تازه بساز، هر دو مقدار را موقت بده، setup را انجام بده و سپس حذف کن. |
| پایگاه دردسترس نیست | شبکه، نقش و پایگاه، TLS و مسیر CA | اتصال و readiness را درست کن؛ TLS production را ضعیف نکن. |
| مالکیت گرفته نمی‌شود | API دیگر یا job تعمیر فعال است | مالک قبلی را با روند معمول متوقف کن؛ advisory lock را دور نزن. |
| مالکیت پس از قطع DB از دست می‌رود | فرایند باید بسته بماند | تنها یک runtime را نگه دار و کنترل‌شده دوباره اجرا کن. |
| migration رد می‌شود | ledger تغییرکرده، جدول بیگانه یا build ناهماهنگ | target را خاموش نگه دار؛ build و backup سازگار را به کار ببر. ledger را ویرایش نکن. |
| راه‌اندازی مدیر رد می‌شود | حساب قبلی، proof مصرف/منقضی، origin نادرست | پس از setup وارد شو؛ برای بازیابی آفلاین از راهنمای operator کمک بگیر. |
| ورود زیاد رد می‌شود | محدودیت تلاش یا حساب غیرفعال | تا پنجرهٔ retry صبر کن و از مدیر کمک بگیر؛ از خطا وجود حساب را حدس نزن. |
| عملیات زیرگیت رد می‌شود | نقش، origin، CSRF، grant مخصوص کار | از UI واردشده دوباره مرور کن؛ grant مصرف‌شده را تکرار نکن. |
| origin پشت ingress نادرست است | hostname، HTTPS و peerهای trusted | TLS ingress و forwarded scheme/host را درست کن و CIDR پراکسی را محدود کن. |
| Kubernetes منبعی نمی‌دهد | روشن‌بودن منبع و Role در namespace | فقط دسترسی نام‌فضای مشخص بده؛ Secret یا `cluster-admin` اضافه نکن. |
| Docker production فعال نمی‌شود | socket مستقیم فقط برای توسعه است | تا تنظیم پراکسی محدود mTLS خاموش بماند. |
| اعلان فقط queued است | adapter، نتیجهٔ نهایی و سیاست شبکه | queued رسید تحویل نیست؛ گیرنده را خصوصی بررسی کن، SSRF را باز نکن. |
| هشدار pending یا unknown است | نسخهٔ منبع، تازگی و پنجرهٔ کامل داده | پس از روشن‌کردن منبع، جمع‌آوری نسخهٔ تازه لازم است؛ فاصلهٔ کوتاه‌تر مدرک نمی‌سازد. |
| runtime key رد می‌شود | مالکیت، مجوز، لینک یا فایل تعویض‌شده | کلید قبلی را نگه دار و از recovery پیروی کن؛ خودسرانه عوض نکن. |
| restore رد می‌شود | خالی‌بودن target، نسخهٔ ابزار و build | target خالی تازه و build/آرشیو سازگار بساز. |
| فهرست ناقص دیده می‌شود | صفحه، سقف یا capability منبع | دادهٔ ناقص را کامل فرض نکن؛ راهنمای [کارهای باز](../roadmap.fa.md) را ببین. |
| history پس از cleanup رشد دارد | سهم batch و ردیف‌های محافظت‌شده | ظرفیت و backup را بسنج؛ ممیزی بدون cutoff بایگانی تأییدشده پاک نمی‌شود. |

برای گزارش، نسخه و commit، نوع نصب، زمان UTC، کد امن خطا، request ID و بازتولید
ساختگی کوچک را ثبت کن. گزارش امنیتی را از مسیر خصوصی
[سیاست امنیت](../../SECURITY.md) بفرست.
