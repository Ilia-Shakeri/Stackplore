# پایش و واکنش رخداد

Stackplore زنده‌بودن پردازه، آمادگی سرویس و دسترس‌پذیری هر منبع را جدا می‌سنجد.
پردازه می‌تواند زنده باشد ولی به‌خاطر PostgreSQL، ledger migration یا مالکیت
تک‌نویسنده آماده نباشد. خرابی یک provider در وضعیت همان منبع می‌آید و لزوماً
readiness کل را خراب نمی‌کند.

## بررسی روزانه

- `/healthz` پاسخ‌گویی پردازه را می‌سنجد؛ پیش از فرستادن درخواست کاربر،
  `/readyz` را هم بررسی کن.
- `/metrics` فقط از CIDRهای `STACKPLORE_METRICS_ALLOWED_PREFIXES` و origin دقیق
  تنظیم‌شده قابل دسترس باشد؛ endpoint را به ingress عمومی نده.
- log ساختاریافته را با دسترسی محدود نگه دار. فیلدها پاک‌سازی و محدود می‌شوند،
  ولی log و خطای provider هنوز می‌تواند زمینهٔ عملیاتی حساس داشته باشد.
- تغییر readiness، تازگی/پوشش منبع، نتیجهٔ نهایی اعلان، ظرفیت پایگاه و رشد ممیزی
  را دنبال کن. دادهٔ stale یا ناموجود را صفر یا منبع سالم فرض نکن.
- backup بومی را دوره‌ای در DB خالی restore و بررسی کن. موفقیت فرمان backup به
  تنهایی مدرک بازیابی نیست.

## پاسخ به رخداد

1. زمان UTC، نسخه، commit، نوع نصب، کد امن خطا و request ID را ثبت کن. credential،
   URL کامل، cookie نشست، payload و راز provider را در گزارش نگذار.
2. `/healthz`، `/readyz`، اتصال/TLS پایگاه، ledger و مالکیت runtime را بررسی کن.
   وضعیت دقیق و بخش کوتاه و امن log را نگه دار.
3. هنگام خرابی منبع، آن را تا بررسی نمایهٔ اپراتور و مجوز خاموش/ایزوله نگه دار.
   برای بازگرداندن مشاهده، خواندن Secret، endpoint دلخواه یا مسیر میزبان را مجاز نکن.
4. اگر نتیجهٔ عملیات زیرگیت نامعلوم است، intent/result پایدار و وضعیت provider را
   پیش از retry بررسی کن. تأیید یک‌بارمصرف یا grant دوباره‌احراز را replay نکن.
5. در احتمال از دست‌رفتن داده، نوشتن را با rollout تک‌مالک متوقف کن، پایگاه خراب
   را نگه دار و مسیر [backup/restore](backup-restore.fa.md) را روی target خالی تازه
   اجرا کن.
6. اگر احتمال افشای credential هست، آن را در secret store اپراتور rotate کن؛
   تحویل‌های pending را reconcile و سرویس مالک را طبق روال restart کن. مقدار قدیم
   یا تازه را در گفتگو یا گزارش نگذار.
7. بازیابی را جداگانه ثابت کن: readiness، ورود، خواندن نمونه، تازگی منبع، audit،
   لغو session بازیابی‌شده و checksum پشتیبان.

برای میان‌بر، `docker compose down --volumes` نزن، PVC را پاک نکن، ledger را ویرایش
نکن و API دوم بالا نیاور. رخداد امنیتی را از مسیر خصوصی
[سیاست امنیت](../../SECURITY.md) گزارش کن.

[عیب‌یابی](troubleshooting.fa.md)، [ارتقا/برگشت](upgrade-rollback.fa.md) و
[ماتریس تست](../testing.md) مرز مدرک را روشن می‌کنند.
