# Troubleshooting

Start with safe process codes and `/healthz` versus `/readyz`. Liveness means
the process answers; readiness additionally checks the current database/ledger
and runtime ownership. One provider being unavailable need not fail global
readiness. Do not send raw environment, credentials, logs or notification URLs
to support channels.

| Symptom                                              | Check                                                                                        | Safe next action                                                                                                                                            |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Process fails before listen                          | Startup fixed error code and configuration names                                             | Compare [configuration](../configuration.md); correct names/canonical values without printing values.                                                       |
| Fresh Compose/chart API exits                        | Empty install, wildcard API bind, missing/expired paired setup proof                         | Generate proof using [setup](account-recovery.md), supply both for first boot, complete setup, then remove them.                                            |
| Database unavailable                                 | Private network, role/database, verified TLS and certificate path                            | Restore connectivity; verify readiness. Do not downgrade production TLS.                                                                                    |
| Ownership unavailable                                | Another API or offline maintenance job uses the installation                                 | Stop the intended old owner through normal deployment control; do not bypass the advisory lock.                                                             |
| Ownership lost after database connection reset       | Runtime stops and refuses to reacquire silently                                              | Ensure only one process, then perform controlled restart.                                                                                                   |
| Migration rejected                                   | Changed/unknown ledger, foreign tables, wrong application version                            | Keep target offline; use matching build/backup. Never edit ledger rows.                                                                                     |
| First setup denied                                   | Existing first account, wrong/expired/reused proof, wrong origin                             | Use login after successful setup. Recover through the offline operator command if ownership is lost.                                                        |
| Login fails repeatedly                               | Coarse login response, throttles, disabled account                                           | Wait for bounded retry; ask an administrator. Do not infer account existence from the error.                                                                |
| Unsafe action rejected                               | Current role, exact origin, CSRF, current purpose-bound grant                                | Retry through the current authenticated UI; never reuse a consumed grant.                                                                                   |
| Browser origin/auth failure behind ingress           | Exact public HTTPS host, edge trust and forwarded scheme/host                                | Use configured TLS ingress; narrow proxy trust to actual peers.                                                                                             |
| Kubernetes source unavailable                        | Enabled in-cluster or mounted profile, exact namespaces, current reader rights and verified CA | Follow the [profile guide](../kubernetes-provider.md); inspect safe reason codes. Keep Secret values and `cluster-admin` outside reader authority. |
| Docker cannot enable in production                   | Direct socket development profile rejected; restricted HTTPS/mTLS reference missing or invalid | Use the implemented [restricted proxy profile](../docker-provider.md). Verify its fixed origin, CA/client certificate and GET allowlist privately. |
| Webhook/Matrix test queued but no receipt            | Selected adapter, terminal delivery/attempt result, safe receiver/network policy             | A queue is not receipt. Review the receiver privately; do not loosen SSRF/redirect policy. Never replay a consumed recent-auth grant.                       |
| Alert stays pending or unknown                       | Current source version, raw collection result, complete fresh window and resource capability | Re-enabling needs a new-version collection. Shorter evaluation intervals do not create missing evidence. See [alert semantics](../alerts-notifications.md). |
| Alert stream resets after reconnect                  | Source/installation identity, retained position and pruning watermark                        | Refetch paginated state. A zero-position snapshot clears the native cursor; an empty alert page alone does not.                                             |
| Matrix retry may duplicate after credential rotation | Same device/endpoint context and persisted delivery identity                                 | Reconcile pending deliveries before changing operator credentials or destination. Do not claim cross-device transaction deduplication.                      |
| Runtime key rejected                                 | Directory ownership/permissions, replaced/symlink/hardlink file                              | Preserve the existing private key; follow recovery policy, not ad hoc replacement.                                                                          |
| Restore rejected                                     | Target not empty, wrong archive/build, incompatible native tools                             | Use a new disposable empty target and [restore procedure](backup-restore.md).                                                                               |
| Large view looks partial                             | Page/capability state and current frontend paging limits                                     | Do not read partial data as complete; see [remaining work](../roadmap.md).                                                                                  |
| Source cache stale after disable or outage           | `source.disabled`, collection attempt and optional-port state                                | History remains; live logs stop on disable. Review the [collection policy](../observations.md).                                                             |
| Source preview fails                                 | Exact current version, operator profile, two-minute expiry and current role                  | Reload state and review again. Missing profiles cannot enable; never automatically replay an uncertain write.                                               |
| Source registry exceeds runtime bound                | At most 64 registered profiles and startup's safe reason                                     | Review operator-owned registry offline. Do not silently skip sources or delete their history.                                                               |
| History grows despite cleanup                        | Effective retention, fair bounded batches and newest/synthetic/protected exclusions | Monitor capacity and verified native backups. Audit expiry needs a monotonic operator-verified archive cutoff; it will not prune without one. |
| Helm private-runtime init fails | Directory/key owner, mode, regular-file size/link count; legacy and private keys both present | Keep the PVC and existing key. Resolve the exact storage state using [deployment](deployment.md); never replace a key or weaken validation to force startup. |
| Source creation/startup fails at audit quota | Current protected audit capacity and once-only `source.create` transaction | Preserve data. Review capacity and verified archive policy; source row and its creation audit must commit together. Do not delete audit facts to bypass capacity. |
| Resource health history empty/denied | Exact owning source/resource, current authority, time range and history capability | Correct selection; a denied current resource cannot expose old facts. Use at most 200 samples and a 30-day API range; do not invent healthy samples. |
| Event page differs after a shared filter | `event_q`, severity, `environment_id`, source/time and cursor | These filters apply before server pagination. Change filters with a fresh cursor; a local empty subset is not an estate-wide claim. |
| Mixed event timeline is denied despite existing operation/alert facts | Source's native `EventHistory` capability | Expected fail-closed behavior: the entire feed is denied/empty. A separate safe system subfeed is not exposed; do not widen provider permissions to manufacture a partial success. |
| Log download denied or incomplete | Current account, operator capture/export policy, fixed target/time and completion marker | No incomplete file is saved. Wait for admission capacity or narrow filters/range; retain 10-second/1-MiB/1,000-output/10,000-scan/100-page limits. |
| Offline page shows no old resources | Network state and public offline shell | Expected: the four cached public files contain no private app/API/log history. Restore connectivity; do not enable API caching. |
| Update waits rather than reloading | Waiting service worker and visible update action | Choose update when ready. The application does not silently reload an active view. |
| Old page rows disappear after a filter change | Source/query identity versus coalesced live refresh | Source/filter changes start a new set; live refresh preserves bounded loaded depth. Check partial/cap notices and avoid interpreting unloaded graph endpoints as absent. |

Before asking for help, record the release/commit, deployment kind, time in UTC,
safe error code, request ID, and a minimal invented reproduction. Private
security reports follow [the security policy](../../SECURITY.md).
Use [monitoring](monitoring.md) for routine probes,
[incident response](incident-response.md) ([فارسی](incident-response.fa.md)) for a
suspected compromise, and [artifact verification](release.md)
([فارسی](release.fa.md)) before replacing a build. Current candidate acceptance
and each customer's installation evidence remain separate.
