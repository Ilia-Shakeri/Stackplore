# Smart Assistant threat model and verification matrix

[Roadmap](../roadmap-v2.md) · [Evaluation](evaluation.md) · [فارسی](#فارسی)

Status: proposed stage-0 controls and required tests. Controls below are not implemented merely because this matrix exists. Existing [security](../security.md), [read-only operation decision](../adr/0006-read-only-and-guarded-mutations.md), [PostgreSQL decision](../adr/0011-postgresql-primary-persistence.md), and [stream decision](../adr/0004-server-sent-events.md) remain authoritative until new decisions are accepted.

## Assets and trust boundaries

Protect current browser/session authority, provider credentials and write identities, infrastructure metadata, private volatile questions/answers, budget reservations, durable run state, and protected audit history. Browser input, returned text, provider labels/logs/events, imported documents, tool results, DNS and network responses are untrusted. A host administrator can read memory or replace code; application policy does not defeat a compromised host.

Boundary: authenticated browser → helper use cases and deterministic policy → bounded normalized read ports → domain evidence projector → approved inference gateway → closed output validator → authorized display/status stream. PostgreSQL owns short transactional run/lease/reservation transitions; no database transaction spans external I/O. The planner proposes; the server authorizes. No service bearer or writer credential enters the context.

V1 roles remain installation-wide. Run-selected sources/environments narrow a question; they do not create a new tenant/source ACL. Conversation ownership is separate and must not grant an administrator automatic access to another user's text. Any future granular ACL requires tests across all ordinary exploration routes and streams, not only the helper.

## Profile and data policy

Remote profile: exact operator-approved HTTPS origin, strict address policy, DNS validation/pinning on every attempt, normal TLS identity, no redirects or ambient proxy, fixed request path and bounded decoding/time. Local profile: exact operator-approved endpoint/network and trust roots; TLS beyond loopback; explicitly approved private addresses only. Reject metadata/link-local/multicast destinations. A local profile must not weaken notification outbound policy. Browser content, prompts and tool responses cannot supply endpoints, paths, resolvers or credentials.

Remote default permits only reviewed structured templates and allowlisted safe fields. Free-form questions, raw log bodies and arbitrary retrieved text stay local. Field names alone do not make their values safe; stage 0 approves value types and projections. Add structural minimization before redaction. Known-secret rejection is additional protection, not a claim of universal detection. Synthetic tests use invented markers, never actual raw tokens, session IDs, provider credentials or mounted secrets.

Raw prompts, answers, tool payloads, logs and internal deliberation are not persisted by default. Volatile context expires within the proposed 30 minutes/eight turns and requires explicit count/byte caps. PostgreSQL retains safe typed goals, references, states, versions and usage metadata. References never bypass current authority or recreate expired context. Conversation deletion must not delete protected audit facts. Deletion does not erase WAL or existing backups; custody and expiry remain operator responsibilities.

A passing fixture is not a claim that the corresponding real integration passed. Add newly discovered threats instead of reshaping cases to pass.

## Cancellation, uncertainty, and audit

Closing the browser stream does not cancel an accepted run; explicit cancellation persists intent. Logout, account or source authority changes, restore and the kill switch invalidate work. Fence queued/replay state first, then cancel owned bounded inference/provider reads and reject late callbacks. Target two seconds after the local revocation signal is observed, not after an undetected upstream permission change. Previously transmitted bytes and remote billing cannot be recalled.

If external dispatch may have occurred and its result/usage is unknown, retain a distinct unknown-charge reservation; never turn missing usage into zero, auto-refund on TTL, silently release it on a new quota period, or replay the external call after restart. Reconcile only with supported usage evidence or an explicit conservative operator settlement, with durable safe audit and preserved period attribution. Ordinary seven-day run metadata may expire only after protected accounting references are detached or retained safely. Retention cannot erase unsettled obligations. Test settlement/retention/quota reset atomically against real PostgreSQL.

Safe audits record actor reference, run/step ID, policy/profile versions, purpose, allowed/denied outcome, bounded reason, counts, timestamps and reservation transition. No bearer, prompt, log body or raw inference response is recorded. Audit capacity/write failures must fail closed before consequential admission or egress where durable intent is required. Results after an accepted intent still need bounded completion/audit recovery; request disconnect cannot erase accountability.

## Infrastructure actions stay outside 2.0

All helper infrastructure tools are read-only. V1 guarded actions retain their own human flow. A later 2.1 proposal handoff may draft only existing supported restart/scale operations and must reuse the current operation service; no direct generated action button or writer tool.

Keep deployment enablement, separate writer permission/identity, administrator, CSRF/origin, purpose-bound recent authentication, exact target/version/capability, preview, one-use confirmation, idempotency, durable intent, bounded provider call and result audit. The helper never receives approval proofs. Drift invalidates proposals. Once an existing operation intent is committed, cancellation cannot promise undo; preserve its durable pending/uncertain receipt and never automatically resend the write. Reverse actions require fresh supported human authorization and audit.

## فارسی

وضعیت: طرح و فهرست تست گام صفر؛ وجود سند، پیاده‌سازی یا قبولی نیست. امنیت و ADRهای فعلی مرجع‌اند. دارایی‌ها: اختیار جلسه، هویت فراهم‌کننده/نویسنده، دادهٔ زیرساخت، متن موقت خصوصی، سهمیه و audit. مرورگر، نام/لاگ/رویداد، سند، پاسخ ابزار/مدل و شبکه نامطمئن‌اند. میزبانِ تصرف‌شده با سیاست برنامه امن نشود.

مرز: مرورگر مجاز → use case و سیاست قطعی → خواندن محدود → شاهد کمینه → درگاه مصوب → خروجی بسته → نمایش/وضعیت مجاز. پردازنده پیشنهاد دهد؛ سرور مجوز بدهد. تراکنش DB بیرون از تماس شبکه بماند. نقش‌های نسخهٔ ۱ نصب‌سراسری‌اند؛ انتخاب محیط ACL تازه نیست. owner گفتگو جدا؛ مدیر حق خودکارِ متن دیگران نگیرد.

پروفایل بیرونی: HTTPS، origin/مسیر ثابت اپراتور، DNS/IP و pin هر تلاش، TLS درست، بدون redirect/proxy محیط، حد زمان/بایت. محلی: مقصد/شبکه/CA مصوب، TLS بیرون loopback، IP خصوصی فقط صریح؛ metadata/link-local/multicast ممنوع. سیاست اعلان‌ها شل نشود؛ متن/مرورگر مقصد یا credential نسازد.

بیرون فقط قالب ساختاری و مقدارهای کمینهٔ مصوب؛ متن آزاد، لاگ خام و سند آزاد محلی بمانند. نام امنِ فیلد، مقدار آن را امن نسازد؛ allowlist و سپس redaction. کشف الگو، نبود راز در همهٔ متن را ثابت نکند. فقط marker ساختگی در تست؛ token/session/proof واقعی نه.

متن خام پرسش/پاسخ/ابزار/لاگ و فکر درونی پیش‌فرض ذخیره نشوند. حافظهٔ موقت سقف زمان، نوبت، تعداد و بایت بخواهد. PostgreSQL فقط هدف نوع‌دار، مرجع، وضعیت، نسخه و مصرف امن نگه دارد. حذف گفتگو audit را cascade نکند؛ حذف DB، پاک‌شدن WAL/backup نیست.

ماتریس بالا برای هر ردیف مالک، فرمان، source/profile/corpus، نتیجه و محدودیت بخواهد. تزریق دستور و ابزار ناشناخته؛ owner/scope و صفحهٔ بعد؛ SSRF/TLS/DNS و wire capture؛ خروجی/استناد و مرورگر؛ idempotency/رزرو/claim و PostgreSQL؛ lease/restore؛ لغو/replay/فشار با HTTP واقعی؛ سقف/soak؛ retention/backup؛ runbook؛ نصب و زنجیرهٔ انتشار جدا آزموده شوند. mock مدرک مرز واقعی نسازد.

قطع صفحه لغو کار نباشد؛ لغو صریح پایدار ثبت شود. خروج حساب، تغییر حق/منبع، restore و کلید توقف کار را باطل کنند. اول صف/replay بسته و پاک؛ بعد لغو و رد جواب دیررس. هدف دو ثانیه پس از سیگنال مشاهده‌شده است؛ کشف مجوز بیرونی جدا. بایت یا هزینهٔ پیشین برنگردد.

dispatch یا هزینه نامعلوم شد، رزرو unknown بماند؛ TTL هفت‌روزه، دورهٔ سهمیهٔ تازه یا لغو، آن را صفر/refund/آزاد نکند. فقط شاهد مصرف معتبر یا تسویهٔ محافظه‌کارانهٔ صریح اپراتور با audit امن. انتساب دوره بماند؛ metadata معمولی تنها پس از حفظ/جداکردن مرجع حسابداری پاک شود. رقابت retention، reset و settlement با PostgreSQL واقعی آزموده شود.

audit فقط مرجع actor، run/step، نسخهٔ سیاست/پروفایل، هدف، نتیجه/دلیل ثابت، شمار، زمان و گذار رزرو داشته باشد. راز و متن خام نداشته باشد. شکست audit لازم، پیش از پذیرش/خروج مهم fail-closed؛ پس از intent پذیرفته‌شده، قطع کاربر نتیجه و حسابرسی را پاک نکند.

همهٔ ابزارهای ۲٫۰ خواندنی‌اند. پیشنهاد restart/scale کار اختیاری ۲٫۱ و فقط جریان انسانی فعلی: enablement، نویسندهٔ جدا، مدیر، CSRF/origin، recent-auth، هدف/نسخه دقیق، preview، تأیید یک‌بارمصرف، idempotency، intent، تماس محدود و audit نتیجه. proof به پردازنده نرسد. لغو گفتگو undo نباشد؛ نتیجهٔ نامعلوم از receipt پایدار، بدون ارسال خودکار دوباره. عمل معکوس هم مجوز و audit تازه بخواهد.
