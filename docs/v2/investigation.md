# Smart Assistant — bounded investigation preparation

Development target **2.0.0-alpha.5**, schema **18**, 2026-11-01.
This plan is preparation; the new investigation mode is not delivered by a
version bump. Alpha.4's chosen local resource journey has complete hosted source
and real desktop proof. Its immutable tag/publication has separate acceptance.

## Intended behavior

An explicit investigation of the selected resource builds a finite server-owned
read plan. Read families are the existing typed inventory, health, metric,
event, topology and locally consented log ports. The planner cannot acquire
shell, SQL, filesystem, mutation, arbitrary endpoint or recursive-call authority.
Returned instructions and fabricated tool names remain inert data.

Every step reserves its durable slot before I/O, then checks current actor,
source/configuration/policy/restore generation, selected-resource scope and
remaining budgets. Reads use bounded pages without following cursors. Missing
permission or revocation stops work; unavailable/unsupported evidence is exposed
truthfully. Logs stay off unless the user explicitly opts in for that local run.

Collected evidence retains its separate sealed read-family proofs. All proofs
must pass fresh authorization before counting, dispatch, publication and citation
resolution. Combined context remains bounded; unavailable outcomes cannot become
invented citation records. One closed answer cites only actual retained items.
Unknown inference usage is never automatically retried or refunded.

The current 120-second run, twelve-tool/three-inference maxima, 64 evidence
records, input/output byte/token bounds, worker/queue limits and volatile lifetime
remain. The explicit CPU profile follows ADR-0017; default timeout stays 25s.
An upper bound does not promise every planned step can finish within the run.

## Implementation and exit work

1. Add the bounded plan and combined evidence/proof ownership with focused
   rejection, truncation, unsupported, revocation and budget tests.
2. Wire an explicit protected request and desktop control, natural English and
   Persian labels, optional local log consent, and generated transport types.
3. Exercise real SQL usage/recovery, cancellation/fencing, poisoning and all
   supported read families. Preserve ordinary explanation behavior.
4. Run complete Actions source/race/install/provider/browser gates and a real
   selected-profile desktop journey. Inspect signed package/security and
   exact-tag results before claiming this checkpoint.

No local services, tests, builds, installs, generators or scans run on the user's
workstation. Local work remains file edits/reads and lightweight Git. Contract
derivation and validation belong on Actions. Desktop remains primary; mobile
keeps a brief smoke check. Optional remote profiles remain disabled/unshipped.
