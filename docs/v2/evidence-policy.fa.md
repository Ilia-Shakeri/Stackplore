# سیاست شاهد و حریم خصوصی Smart Assistant

[English](evidence-policy.md)

وضعیت در ۲۰۲۶-۱۰-۲۵: **منبع نامزد گام ۳؛ قابلیت کامل یا فعال عمومی نیست**.
این سند کد آماده‌سازی فعلی را شرح دهد. پذیرش عمومی، رفتار مرورگر، انتقال
بیرونی، حریم خصوصی استقرار یا پایان گام را ثابت نکند. وضعیت تحویل در
[دفتر گام‌ها](implementation.md) است. قواعد پذیرفته در
[ADR-0014](../adr/0014-read-only-helper-scope-and-boundaries.md)،
[ADR-0015](../adr/0015-helper-durable-runtime-and-volatile-context.md)،
[ADR-0016](../adr/0016-helper-authority-and-egress-policy.md) و بخش ۱۵
[SPEC](../../SPEC.md) پابرجا هستند.

## مرز اجزا

نامزد با یک سرویس Go و PostgreSQL کار کند. این بسته‌ها مسیر HTTP یا ثبت
عمومی ابزار شاهد نسازند. در آماده‌سازی مسیر دستیار، سرور فعلاً فقط نگهداری
فراداده را وصل کند؛ خوانش محتوایی و سرویس توضیح وصل عمومی نشده‌اند. هر مسیر
بعدی باید قرارداد رسمی و تست دسترسی خود را همراه پیاده‌سازی بیاورد.

| جزء                                                                            | کار                                                                   |
| ------------------------------------------------------------------------------ | --------------------------------------------------------------------- |
| [`logsafe.Policy`](../../apps/api/internal/provider/logsafe/policy.go)         | پوشاندن پیش‌فرض و فیلدهای افزوده؛ سیاست تغییرناپذیر و اثر انگشت بسته. |
| [`logpolicy.Reader`](../../apps/api/internal/logpolicy/reader.go)              | تنظیم مؤثر، پوشاندن و برداشت محدود لاگ بیرون از HTTP.                 |
| [`configuredLogReader`](../../apps/api/internal/httpapi/configured_logs.go)    | خوانش HTTP تنظیم‌شده را به همان سیاست مشترک بدهد.                     |
| [`contextbuilder`](../../apps/api/internal/contextbuilder/builder.go)          | فیلدهای مجاز بسته، شناسه ارجاع، کیفیت راست و سقف بایت.                |
| [`assistantevidence.Reader`](../../apps/api/internal/assistantevidence/doc.go) | خوانش نوع‌دار، اختیار زنده، شاهد موقت مهرشده و حل ارجاع.              |
| [`assistantservice`](../../apps/api/internal/assistantservice/service.go)      | نامزد توضیح محلی یک منبع؛ رزرو پایدار و متن موقت.                     |
| [اختیار PostgreSQL](../../apps/api/internal/postgres/assistant_authority.go)   | هدف جدا برای پذیرش/شاهد؛ مالک، نشست، کنترل، منبع و claim جاری.        |

ترکیب مطمئن سرور، providerهای اپراتور را در Reader مشترک ثبت کند. مرورگر و
متن برگشتی نتوانند ابزار ثبت کنند، endpoint یا مسیر میزبان بدهند، نام متریک
عوض کنند، cursor دلخواه دنبال کنند، SQL تزریق کنند یا درگاه shell، exec،
خوانش مقدار Secret و نوشتن provider بگیرند. حق مشاهده مدیر و بیننده همچنان
در کل نصب است؛ انتخاب scope مرز مستأجر یا حق دسترسی تازه برای منبع نسازد.

## شش خوانش ثابت

`ReadRequest` فقط actor مطمئن، run پذیرفته‌شده، scope دقیق منبع/منابع/زمان،
نوع گام بسته، مقصد و رضایت محلی لاگ دارد. فیلد سؤال، URL، مسیر، query آزاد یا
افزونه ندارد. هر درخواست یک خانواده بخواند و cursor بعدی را دنبال نکند.
پاسخ باید از `ValidateFor` دامنه بگذرد.

| خانواده  | خوانش داده ثابت                                                                                         | اثبات اختیار زنده                                                                                               |
| -------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| موجودی   | snapshot همان منابع انتخاب‌شده از خوانش جزئیات.                                                         | برداشت تازه موجودی و پارتیشن همان منابع.                                                                        |
| سلامت    | `GetHealth` برای همان منابع.                                                                            | موجودی تازه و خوانش واقعی سلامت؛ snapshot هر منبع available و complete باشد.                                    |
| متریک    | `GetMetricHistory` با حداکثر ۶۴ نقطه؛ فقط مصرف CPU، مصرف حافظه و شمار راه‌اندازی دوباره.                | موجودی تازه و متریک جاری واقعی با همان نام‌های ثابت برای همه منابع انتخاب‌شده.                                  |
| رخداد    | یک صفحه `ListEvents` با سقف ۶۴، scope و بازه دقیق؛ بدون جست‌وجوی متن آزاد.                              | موجودی تازه و query معتبر رخداد با سقف یک مورد.                                                                 |
| توپولوژی | یک صفحه رابطه با سقف ۶۴؛ فقط یال با دو سر انتخاب‌شده بماند. یال حذف‌شده، باقی‌ماندن داده را علامت بزند. | موجودی تازه و query واقعی رابطه با سقف یک مورد. اثبات partial رد شود؛ یال مشتق شاید به پارتیشن سوم وابسته باشد. |
| لاگ      | `Capture` مشترک با هدف/بازه انتخاب‌شده؛ حداکثر ۶۴ خط پیش از تنظیم مؤثر و ۳۲KiB متن.                     | موجودی تازه، خوانش لاگ با همان سیاست مشترک، رضایت محلی و بررسی دوباره همان query و سیاست.                       |

`CaptureAuthority` باید provider واقعی متصل به اپراتور را بگیرد؛ خواننده
مشاهده ذخیره‌شده کافی نیست. `Source.Read` می‌تواند داده ذخیره‌شده معتبر
بدهد؛ enum پشتیبانی به‌تنهایی اختیار زنده ندهد. درگاه مفقود، پارتیشن denied،
شناسه نابرابر یا اثبات زنده ناموجود، دسترسی را ببندند. اثبات زنده باید
available، بدون زمان آینده و حداکثر پنج ثانیه کهنه باشد. Demo زمان مصنوعی
ثابت دارد و فقط از سنجش سن معاف است. این قاعده قول کشف لغو مجوز در پنج ثانیه
نیست؛ لغو هنوز دیده‌نشده را اندازه نگیرد.

ناموجود و پشتیبانی‌نشده با denied یکی نیستند. متریک مفقود صفر نیست. صفحه
partial اسکن کامل نصب نیست. خوانش‌ها snapshot اتمی یکسان نیستند؛ زمان و
کیفیت خود را نگه دارند.

## فیلدهای مجاز بسته

سند، نسخه، handle منبع، نوع provider، نسخه پیکربندی منبع، نسخه سیاست، نسل
restore، بازه دقیق UTC، کیفیت و `more_available` دارد. کیفیت شامل وضعیت
دسترسی، کامل‌بودن، زمان مشاهده و پرچم مصنوعی است. هر رکورد، شناسه ارجاع سرور
و نوع بسته خود را دارد.

| رکورد    | فیلدهای افزوده مجاز                                                                     |
| -------- | --------------------------------------------------------------------------------------- |
| منبع     | handle نرمال منبع، handle بسته نسخه اگر موجود و وضعیت سلامت امن.                        |
| سلامت    | handle منبع و سلامت نرمال موجودی؛ متن توضیح و پیام شاهد سلامت حذف شوند.                 |
| متریک    | handle منبع، نام/واحد بسته، عدد متناهی، زمان نمونه و فاصله بر حسب ثانیه کامل.           |
| رخداد    | handle منبع، شدت و زمان رخداد؛ summary، متن آزاد kind/reason و سایر نثر رخداد حذف شوند. |
| رابطه    | handle دو سر، نوع/جهت بسته و provenance/certainty/confidence معتبر.                     |
| لاگ محلی | handle منبع، زمان، شدت، stream، متن پس از سیاست و پرچم پوشاندن/برش.                     |

نام نمایشی بررسی‌نشده، شناسه native، label، annotation، متن آزاد منبع، نسخه
خام، summary رخداد، نثر سلامت، متن runbook و مقصد کامل اعلان افزوده نشوند.
رمز و credential حتی در مقصد محلی هم ممنوع بمانند. پوشاندن الگوهای شناخته‌شده
اثبات پاک‌بودن هر متن آزاد نیست؛ ساخت نمایش مجاز می‌تواند رد شود.

شناسه ارجاع، `ev_` و ۶۴ رقم hexadecimal کوچک است. به run سرور، منبع، نسخه‌ها،
نسل restore، بازه دقیق، هویت شیء و محتوای رکورد پیوند دارد. خروجی Items شناسه
را دوباره نسازد و رکورد را عوض نکند. handle منبع/منابع/نسخه/دو سر رابطه در
مقصد remote نیز مخصوص یک run است. هویت دقیق lookup در نگاشت محلی بماند؛ به
payload بیرونی نرود. handle حق دسترسی، لینک آزاد یا action نیست.

## سقف محتوا و قاب انتقال

| مرز                                  | سقف سخت                                                                                             |
| ------------------------------------ | --------------------------------------------------------------------------------------------------- |
| ثبت منبع در هر Reader                | ۶۴؛ SourceIDها یکتا باشند.                                                                          |
| منابع هر خوانش                       | ۳۲ مورد یکتا از همان منبع دقیق.                                                                     |
| بازه Reader                          | ۲۴ ساعت؛ لاگ حداکثر ۱۵ دقیقه.                                                                       |
| سازنده پایه                          | ۲۵۶ رکورد و ۶۴KiB سند سریال‌شده؛ caller سقف کوچک‌تر بتواند بدهد.                                    |
| Reader و export فعلی                 | حداکثر ۶۴ رکورد/item، همراه سقف بایت سخت‌تر.                                                        |
| هر `Item.Text`                       | ۸۱۹۲ بایت JSON معتبر.                                                                               |
| آرایه صریح `[{"id":...,"text":...}]` | ۶۵۵۳۶ بایت با ID، escape رشته، کروشه و ویرگول.                                                      |
| نمایش لاگ محلی                       | سقف طراحی ۲۰۰ خط، ۳۲KiB متن، هر خط ۴۰۹۶ بایت UTF-8؛ این Reader پیش از settings حداکثر ۶۴ خط بخواهد. |
| ورودی کامل پردازشگر                  | سقف جدا ۶۴KiB متن قالب‌خورده و ۱۶۰۰۰ token ورودی شمارش‌شده معتبر.                                   |

[`Bundle.Items()`](../../apps/api/internal/contextbuilder/items.go) دور هر رکورد
دست‌نخورده، کل قاب منبع/نسخه/بازه/کیفیت را تکرار کند. `item_index` از صفر و
`item_count` کل را اضافه کند. ID و reference، متن تک‌مورد و آرایه escape‌شده
را چک کند. یا همه itemها را بدهد یا خطای ثابت سقف/اعتبار با خروجی nil؛ prefix
نیمه ندهد. واقعیت انتخاب‌شده پنهان حذف نکند و محتوای ارجاع‌خورده را برای
جا‌شدن نبرد. خط ۴KiB پس از escape شاید از ۸KiB بگذرد؛ آن وقت باید رد شود.
برش UTF-8 پیش از ساخت ارجاع، پرچم روشن دارد. داده صفحه بعد علامت بماند.

بسته خالی معتبر، آرایه خالی بدهد و ارجاع نسازد. آرایه خالی، سالم یا کامل بودن
زیرساخت را ثابت نکند؛ use case وضعیت ناموجود/پشتیبانی‌نشده را نگه دارد. سرویس
توضیح اولیه دقیقاً یک item منبع بخواهد؛ خروجی خالی یا نابرابر را رد کند.

سقف آرایه، کل prompt نیست. locale، سؤال، متن سیستم، JSON/schema/template و
tokenهای ویژه هنوز اعتبارسنجی کل ورودی و شمارنده دقیق پیش از dispatch
بخواهند. تخمین بایت یا usage برگشتی پس از تولید، این اثبات نیست.

## یک سیاست مشترک لاگ

wrapper تنظیم‌شده HTTP، `logpolicy.Reader.ReadLogs` را بخواند. تنظیم معتبر
برنامه را پیش از provider دوباره بگیرد و سقف خط کوچک‌تر میان query و تنظیم
مؤثر را اعمال کند. پوشاندن پیش‌فرض provider حفظ شود و فیلدهای افزوده اعمال
شوند. خوانش دستیار از `Capture` بگذرد؛ این راه همیشه پوشاندن پیش‌فرض و افزوده
را دوباره اعمال، صفحه را اعتبارسنجی و کپی‌ها را مهر کند. صفحه خام provider
جای capture ننشیند.

`logsafe.Policy` نام فیلدهای افزوده تغییرناپذیر را نرمال و مرتب کند و همراه
هویت نسخه‌دار سیاست پیش‌فرض در اثر SHA-256 بگذارد. ترتیب، بزرگی حرف و
جداکننده معادل، اثر یکسان دهند. عوض‌شدن منطق پوشاندن پیش‌فرض، هویت نسخه‌دار
جدید بخواهد. فیلد افزوده حفاظت پیش‌فرض را کم نکند.

اثر capture شامل اثر سیاست، همان snapshot واقعی
`application_settings.Version` مصرف‌شده پیش از خوانش، سقف مؤثر خط و بایت، سقف
بایت/rune خط، طول بازه query و سقف lookback است. هدف، متن، هویت منبع و زمان
مطلق در آن نیست. fixture بدون settings از نسخه صفر استفاده کند؛ ثبت شاهد
تولیدی settings reader بخواهد. capture بی‌مهر اثر صفر دارد و نامعتبر است.
تغییر هویت masking در میان خوانش، نتیجه را رد کند.

شاهد مهرشده لاگ، رضایت و این اثر را نگه دارد. پیش از مصرف متن یا حل ارجاع،
همان query مطمئن محدود دوباره Capture شود و اثر سیاست سنجیده شود. probe
تک‌خطی مجوز، جای این مقایسه نیست. متن تازه دور ریخته شود؛ جای متن قدیمی
ارجاع‌خورده ننشیند. تغییر نسخه settings، فیلد پوشاندن یا سقف مؤثر، متن قدیم
را باطل کند؛ حتی اگر ID ارجاع هنوز هست. تغییر پیکربندی فیلدهای افزوده باید
سیاست مشترک هر دو مسیر را جایگزین و محتوای موقت وابسته را باطل کند.

## اختیار، pin منبع و ارجاع مهرشده

`AuthorizeAdmission` فقط candidate با نسخه صفر و فراداده جاری را بسنجد؛
provider نخواند و دسترسی run ذخیره‌شده ندهد. `Authorize` فقط فراداده run
ذخیره‌شده را چک کند. poll وضعیت از خوانش repository متعلق به مالک بگذرد و به
رسیدن provider وابسته نباشد. هیچ‌کدام متن آزاد نکنند؛ مصرف محتوای جمع‌شده
`AuthorizeEvidence` لازم دارد.

Gate فراداده، نشست/auth revision جاری، مالک، نقش نصب، کنترل/profile/policy،
فعال‌بودن و پیکربندی منبع و نسل restore را ببندد. پذیرش و شاهد ذخیره‌شده دو
متد repository جدا دارند. snapshot صف/کامل‌شده دقیق برابر باشد. در run جاری
فقط پیشروی نسخه/زمان/شمارنده/lease در همان attempt، fence، مالک lease و هویت
ثابت مجاز است. snapshot آینده یا عوض‌شده رد شود. این قاعده خوانش، شرط
compare-and-swap نوشتن را سست نکند.

`Source.ConfigurationVersion` ثبت‌شده مثبت و برابر
`Scope.ConfigurationVersion` و `Run.SourceVersion` باشد. این نسخه منبع است؛ با
`Run.ConfigurationVersion` جداگانه کنترل اجرا یکی نیست. SourceID یکسان با
نسخه جدید، adapter ثبت‌شده قدیم را مصرف نکند.

فیلدهای `Evidence` خصوصی‌اند؛ به همان نمونه Reader، actor/نشست، run پذیرفته،
scope، خانواده خوانش و سیاست لاگ محلی مهر دارند. reference ساخته caller یا
مقدار صفر، مهر معتبر نسازد. عمر موقت تا ۳۰ دقیقه پس از پذیرش است. انتظار
برای slot نیز از این عمر و در run جاری از lease و deadline باقی‌مانده کوتاه‌تر
باشد.

بررسی محتوا، فراداده جاری و همان خانواده زنده را دوباره بسنجد؛ لاگ سیاست
مؤثر را هم دوباره بسنجد. حل ارجاع، همان مالک/نشست و attempt و run موفق
کامل‌شده با fence بعدی مورد انتظار و نسخه جدیدتر بخواهد. فقط نوع بسته و
locator نرمال برگردد؛ transport آن را به نمای ثابت مجاز خود ببرد. ID ناشناخته،
Reader دیگر، scope/config/policy/restore عوض‌شده، متن منقضی و usage نامطمئن رد
شوند.

چرخش منبع، الزام ترکیب سرور است؛ دستور hot reload منتشرشده نیست:

1. تغییر پیکربندی و نسخه منبع از use case صاحب آن commit شود؛ اختیار جاری
   پایگاه نسخه قدیمی را ببندد.
2. پیش از cancel کار، متن موقت قدیمی منبع fence و پاک شود؛ مسیر invalidation
   منبع در سرویس صاحب آن استفاده شود.
3. providerهای متصل به اپراتور و Reader مشترک تازه با pin دقیق جدید و همان
   سیاست مؤثر لاگ ساخته شوند؛ اتصال قدیمی کنار رود.
4. کار تازه و مجاز لازم باشد. شاهد قدیم به Reader جدید منتقل نشود و فراخوانی
   نامطمئن خودکار دوباره نرود.

## دو مسیر محدود مستقل

| مسیر           | کار                                  | حد                                                                                 |
| -------------- | ------------------------------------ | ---------------------------------------------------------------------------------- |
| فراداده        | بررسی پذیرش و فراداده run ذخیره‌شده. | دو slot؛ حداکثر سه ثانیه با انتظار slot، یا deadline تنظیم/والد کوتاه‌تر.          |
| provider/محتوا | خوانش، اختیار متن و حل ارجاع.        | دو slot؛ حداکثر ۲۵ ثانیه با انتظار slot؛ lease/run/عمر موقت می‌تواند کوتاه‌تر کند. |

دو خوانش provider مسدود، slot فراداده لازم برای مالکیت و پیشروی lease را
نگیرند. Reader کار پس‌زمینه، cursor loop یا صف بی‌حد نسازد. نمونه آن باید
مشترک باشد؛ ساخت یکی برای هر درخواست سقف کل نصب را اعمال نکند. سقف worker،
پایگاه، پذیرش و transport همچنان جدا لازم است.

یک رزرو منطقی خوانش می‌تواند چند بررسی محدود داشته باشد: حداکثر چهار برداشت
موجودی، سه probe خانواده، سه دور روی منابع انتخاب‌شده با سقف ۳۲ مورد، شش
بررسی فراداده، یک خوانش capability و یک خوانش داده خانواده. لاگ یک Capture
همان query و بررسی نهایی فراداده هم اضافه کند. همه context همان خوانش را
دارند. این‌ها اعتبارسنجی‌اند؛ action اضافی منتخب پردازشگر نیستند. شمارها سقف
کد هستند؛ اندازه‌گیری ظرفیت یا تأخیر نیستند.

## ورودی محلی، remote و نخستین ارسال متن

سؤال آزاد محلی محدود و موقت بماند. رضایت لاگ محلی صریح باشد؛ حفاظت فیلدها
را برندارد و انتقال لاگ به بیرون را مجاز نکند. نامزد سرویس فعلی فقط توضیح
موجودی محلی بدون هزینه برای یک منبع دارد؛ Reader شش‌خانواده‌ای آماده‌سازی
وسیع‌تر است.

نمایش remote فقط فیلد ساختاری و handle بسته مخصوص run بدهد و Capture لاگ را
رد کند. این نمایش مجوز پردازشگر بیرونی نیست. gateway عمومی فیلد `Question`
جدا دارد؛ ترکیب remote آینده باید فقط template بررسی‌شده سرور و پارامتر
نوع‌دار بدهد. سؤال آزاد، متن لاگ، annotation، نثر رخداد یا runbook در آن
کپی نشود. این نامزد workflow عمومی یا adapter remote فعال نکند. متن گسترده‌تر
تصمیم پذیرفته جدا، فعال‌سازی اپراتور، اطلاع‌رسانی و اثبات wire در ADR-0016
بخواهد.

Prepare هم متن بفرستد: شمارنده محلی پیش از تولید، endpoint قالب/tokenization
همان سرویس بسته را صدا بزند. نامزد سرویس پس از رزرو inference و **پیش از
`Gateway.Prepare`** اختیار متن مهرشده را دوباره بسنجد؛ پس از Prepare و پیش
از Dispatch و نیز پیش از انتشار/بازخوانی هم بسنجد. بررسی فقط پیش از تولید
برای نخستین درخواست حامل متن دیر است. قید شبکه profile و شمارش کل token
همچنان لازم‌اند؛ [راهنمای profile محلی](local-profile.md) را ببینید. لغو بعدی
بایت فرستاده‌شده را پس نگیرد.

## حافظه موقت، پایگاه و telemetry

سؤال، بدنه نمایش‌شده، متن لاگ، tokenهای شمارش‌شده و متن پاسخ در حافظه خصوصی
محدود بمانند. سرویس صاحب، تاریخچه را به ۳۰ دقیقه یا هشت نوبت محدود و در
expiry، cancel، لغو نشست/منبع، خاموشی و از‌دست‌رفتن مالکیت fence و پاک کند.
متن گم‌شده پس از restart بازسازی نشود. فراداده نوع‌دار و usage حل‌نشده چرخه
جدا در [راهنمای runtime](runtime.md) دارند؛ پاک‌سازی عادی usage نامعلوم را
آزاد نکند.

محتوای خام به SQL، audit، telemetry، payload خطا، crash report، cache آفلاین/
service-worker و replay پایدار نرود. کد امن خطا فقط
`assistant.evidence_invalid`، `assistant.evidence_denied`،
`assistant.evidence_unavailable`، `assistant.evidence_budget` و
`assistant.evidence_cancelled` است؛ متن خطای بالادست عبور نکند.

fmt/JSON معمول wrapperهای request، bundle، item، capture، policy و شاهد مهرشده
متن خصوصی را پنهان کنند. JSON صریح bundle، `Item.Text`، فیلد درونی انتقال و
بخش پاسخ دسترسی عمدی به متن روشن هستند؛ لاگ نشوند. این نگهبان‌ها قول پاک‌شدن
فیزیکی هر کپی runtime یا حذف از backup قدیمی ندهند. نگهداری provider و حریم
خصوصی میزبان اثبات استقرار جدا بخواهند.

## تست و دروازه‌های باز

تست محدود masking/capture/projection، Reader/service و رفتار مشترک HTTP لاگ
پاس شد. در ۲۰۲۶-۱۰-۲۵، تست واقعی PostgreSQL برای نتیجهٔ پذیرش پس از commit،
rollback، اختیار جاری و یک ارسال مستند هم پاس شد؛ یک بار با backend ساختگی و
یک بار با adapter واقعی HTTP و سرور محدود مصنوعی. هر مسیر حامل متن، رزرو
commit‌شده را دید؛ فیلدهای بستهٔ wire و همهٔ جدول‌های متعلق به تست برای نبود
متن خصوصی بررسی شدند. این تست، موتور واقعی، مجوز provider مستقر، حریم telemetry
یا کیفیت پاسخ انسانی را ثابت نکند. [رسید نامزد](../evidence/2.0.0-alpha.3/README.md)
را ببین. گیت کامل، تست میزبان روی همان منبع و سنجش پذیرفتهٔ شاخه هنوز جدا هستند.

پس از آماده‌کردن [ابزارهای pinned](../development.md)، فرمان‌های محدود:

```powershell
go -C apps/api test -p 1 ./internal/provider/logsafe ./internal/logpolicy ./internal/contextbuilder -count=1 -timeout=2m -cover
go -C apps/api test -p 1 ./internal/assistantevidence ./internal/assistantservice -count=1 -timeout=2m -cover
npm.cmd run verify
```

منبع دقیق نامزد، نسخه ابزار، log کامل، exit و نوع coverage ثبت شوند. پوشش
statement، هدف پذیرفته پوشش branch را ثابت نکند. تست migration/authority/claim
fixture PostgreSQL واقعی و ایزوله بخواهد؛ mock اثبات SQL نیست. موارد منفی
شامل چرخش نسخه منبع، تغییر مالک/نشست/نقش/profile/policy/restore، claim آینده یا
کهنه، لغو همان خانواده، سیاست لاگ عوض‌شده، خوانش مسدود همراه ادامه کار فراداده و
لغو، لغو پیش از Count، شاهد خراب/بزرگ، UTF-8/escape، ارجاع ساختگی و داده
خصمانه که فقط داده بماند هستند.

پیش از فعال‌شدن هر route محتوای تولیدی، درخواست مصنوعی همه profileهای
پشتیبانی‌شده ضبط و فهرست دقیق مجاز، شمارش کل ورودی و نبود سؤال/لاگ خام remote
ثابت شوند. اختیار جاری در Count، dispatch، انتشار و replay سنجیده شود؛ خروجی
پایگاه/telemetry/cache برای نبود متن خام بررسی شود. هنگام ساخت سطح عمومی،
اثبات قرارداد و مرورگر دوزبانه صاحب آن هم افزوده شود. شکست‌ها و محدودیت‌ها
در دفتر گام‌ها حفظ شوند.
