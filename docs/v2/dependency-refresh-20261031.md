# Dependency refresh — 2026-10-31

Development **2.0.0-alpha.4**. This refresh changes the locked browser/runtime
serializer and a development-only glob matcher. Earlier October 28 scan receipts
remain historical evidence for their exact source and advisory data.

A new all-severity package audit reported three high and three moderate findings
in the 393-version graph. The high-severity report alone omitted moderate
advisory details, so the complete advisory set was obtained with the low-level
threshold before selecting final fixes. No advisory is ignored.

The intermediate serializer `1.6.8` fixed the high findings but left two
moderate serializer findings; it is not the final accepted graph. The existing
serializer override now pins `1.6.11`. A narrow override replaces only
`minimatch@10.2.5` with `11.0.1`. The matcher retains CommonJS and ESM entry
points and supports the pinned Node 24 runtime. Its extra matcher dependency
increases the locked inventory to **394 versions**. Exact integrity entries
are regenerated by the pinned package manager; application/tool versions and
release-age policy remain unchanged.

Production legal metadata is regenerated from the installed locked graph:
**63 exact packages and 63 upstream legal files**. The all-severity package audit
after the final pins reports zero findings. That package audit does not replace
fresh source scanning, full verification or exact-commit hosted checks.

The previous status-server snapshot passed functional checks before the new
advisory refresh; it contains the old graph and must not certify the changed
dependency bytes. A separate clean snapshot and source-bound receipt are
required for final checks. Keep failed/intermediate audit and database-download
receipts. Do not disable TLS, skip source analysis or relabel stale database
results as a current scan. The [scanner documentation](https://trivy.dev/docs/latest/configuration/db/)
lists official database repositories and their fallback behavior.

No claim is made about exploit reachability in the current application, complete
product acceptance, a current processor or a new release tag.

and `golang.org/x/net` **0.62.0**. The selected graph advances `x/crypto`

[GO-2026-5932](https://vuln.go.dev/ID/GO-2026-5932.json) concerns the deprecated
`golang.org/x/crypto/openpgp` package family and has no fixed version. Keep this
unknown-severity finding visible in the all-severity source report. Fresh
`go list -mod=readonly -deps` inventories for operator, server and storage on
all five supported release targets contain none of the affected imports.
Those inventories bind the module-file and sorted-import hashes. This evidence
covers default release build tags only; it does not certify arbitrary builds.
Retain `x/crypto` for Argon2id; removing password protection is not a remedy.

Record the existing HIGH/CRITICAL policy gate separately from the stricter
all-severity investigation. No global ignore is added. A passing policy gate
must never be described as zero findings at every severity.
